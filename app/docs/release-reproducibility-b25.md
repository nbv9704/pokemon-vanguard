# B25 — release reproducibility contract (#33)

The supported, checked release format is **source ZIP** only, with `RELEASE-MANIFEST.json` (`schemaVersion:1`, `kind:source`, sorted file names, SHA-256 and byte length). An independently deployable runtime image and debug report are **not** source ZIPs and are not promised by this workflow. The deterministic output contract is **reproducible extracted contents and per-file hashes across platforms**, not identical whole-ZIP bytes across Python/zlib versions. ZIP root, entry order, timestamps and permissions are normalized so two builds with the same tools/input *also* produce byte-identical ZIP files.

`python3 scripts/package-full.py --project-root . --output /tmp/PokemonVanguard.zip` generates a sanitized archive, ignoring `.dev.vars`, user saves, reports, caches, node_modules, backup and admin journals, and symlink/junctions. `python3 scripts/verify-release.py /tmp/PokemonVanguard.zip` checks path traversal, duplicate paths, membership, CRC, hashes and private-path exclusion. Never run the packaging script inside the project tree or place saves under distributed source paths. It does not publish or commit anything.

`node --test tests/release-packaging-b09.test.mjs tests/release-reproducible-b25.test.mjs` validates repeat builds, metadata changes, tamper detection, permission normalization, safe allowlist and no mutation of source files. Prior hosted B24 CI already exercised Ubuntu/Windows installation and check, with an Ubuntu clean-unpack release smoke; a hosted B25 run should be repeated when the project is pushed. `npm run check` now also validates the responsive image inventory and new asset sizes on extracted source. Browser and rights review for #22 are distinct from archive determinism.
